The one idea behind this whole sheet: a relative clause tells you which one (defining: no commas, can't be removed) or gives you extra information (non-defining: commas, can be removed). Choose the pronoun by what it replaces — person → who, thing → which / that, possession → whose, place → where, time → when.

1. The pronouns — one table

ReplacesDefining (no commas)Non-defining (with commas)Example
person (subject)who / thatwho onlyThe dev who wrote the patch is Mark.
person (object)who / that / — (omitted)who onlyThe dev (who) we hired is Mark.
thing (subject)which / thatwhich onlyThe bug which crashed the server is fixed.
thing (object)which / that / — (omitted)which onlyThe patch (which) he shipped worked.
possessionwhosewhoseThe dev whose code broke is Mark.
placewherewhereThe room where we test is upstairs.
timewhenwhenThe day when it broke was a Tuesday.
Two rules that cover almost everything: (1) after a comma, that is never correct — use who or which; (2) if the relative pronoun is the object of the clause, it can be dropped in defining clauses (the dev we hired) but never in non-defining ones (Mark, who we hired, — not Mark, we hired).

3. Defining vs non-defining — the comma decides

TypeFormMeaningExample
Definingno commas, can use that, can drop the object pronountells you which one — the clause is essentialThe developer who wrote the patch is Mark. (there are several developers; this identifies which one)
Non-definingcommas, never that, pronoun cannot be droppedgives extra information — the person/thing is already identifiedMark, who wrote the patch, is on call. (there's only one Mark; the clause just adds info)
Comma changes the meaning: The devs who tested the biometric flow = only the devs who tested it (subset); The devs, who tested the biometric flow, = all the devs, and by the way they tested it.

  1. Mark, wrote the patch, is on call this week.
  2. The developer wrote the patch is on call this week.
  3. The patch, shipped on Tuesday, fixed the login bug.
  4. The patch shipped on Tuesday fixed the login bug.
  5. The biometric flow, we tested last sprint, is still unstable.
  6. The team shipped the patch is getting a bonus.

4. Dropping the object pronoun

Rule: if the relative pronoun is the object of the clause, you can drop it in a defining clause. The dev (who) we hired = The dev we hired. But if it's the subject of the clause, you can't: The dev who wrote it — you can't say The dev wrote it is Mark (that means something else).

And in a non-defining clause, you can never drop it: Mark, who we hired, — not Mark, we hired,.

Exercise 3 — Which is correct?

  1. The developer we hired last month is doing great.
  2. The developer wrote the patch is on call.
  3. Mark, we hired last month, is doing great.
  4. The patch he shipped on Tuesday fixed the bug.
  5. The patch shipped on Tuesday fixed the bug.
  6. The team, had been waiting two weeks, finally resumed.

5. That vs which — where the two overlap

Short version: in defining clauses, both that and which are grammatical — the bug that crashed the server and the bug which crashed the server are both correct. In non-defining clauses (with commas), only which is grammatical. And after a preposition, only which: the tool with which we test — never with that.

So a blank can't have that and which as only options — one of them must be clearly wrong (with a comma, or after a preposition). Where they're interchangeable, both are orange-or-green, never red.

Exercise 4 — Choose the correct option

  1. The bug crashed the server is fixed.
  2. The bug, crashed the server, is fixed.
  3. The tool we test the biometric flow is open source.
  4. The server the tests run went down last night.
  5. The developer I reported the bug fixed it the next day.
  6. The patch landed on Tuesday fixed the login flow.

6. Reduced relative clauses

Short version: you can shorten a relative clause by dropping the pronoun and the auxiliary: the dev who is working on it → the dev working on it; the bug that was fixed on Tuesday → the bug fixed on Tuesday. The reduction always keeps the participle (-ing for active, past participle for passive).

Exercise 5 — Choose the correct reduced form

  1. The developer on the biometric flow is Mark.
  2. The bug on Tuesday is now in production.
  3. The team for the fix lost two weeks.
  4. The documentation by the provider is confusing.
  5. The test on the staging server failed.
  6. The patch last Tuesday broke the login flow.
